# tp125 时区与时间换算工作台

一个本地小工具：把各地时区连同夏令时规则登记进来，再把某一个时刻换算到所有已登记的时区，页面上直接看出各地是当地的几点、谁的日期已经翻到前一天或者后一天、跟来源时区差了几个小时。时区名写得不合规矩、偏移超出范围、夏令时偏移不比标准偏移靠前、开始与结束两段规则写得一模一样、结束年份早于开始年份，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5125>

端口固定为 `5125`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 时区档案区列出时区名称、显示名称、标准偏移、是否实行夏令时、夏令时偏移、切换规则、生效年份与备注；可以按是否实行夏令时筛选，也能按名称、显示名或备注搜索
2. 点新建档案填上时区名与偏移；实行夏令时的档案还要把夏令时偏移与开始、结束两段切换规则（第几个星期几的几点几分）以及生效年份填上
3. 换算台选好日期、时刻与来源时区，勾好要参与换算的地区（可全选或清空），再选日期与时刻的写法偏好（短横线或中文日期、24 或 12 小时制），点换算一遍，页面列出每个勾选时区的当地日期、当地时刻、星期、与来源是否同一天、偏移以及跟来源时区差多少
4. 经常要看的固定一组地区可以存成换算方案：点「把当前选择存为方案」起个名字，方案会记下来源时区、勾选的地区、日期与时刻写法偏好以及存入时间；方案页可以新建、编辑、删除，点「按方案重算」即用换算台上当前的日期与时刻套方案设置再算一遍
5. 方案名不能为空，也不能与已有方案重名；改方案只动方案本身，不会改掉换算台上正在进行的选择，反过来在换算台上改选择也不会动已存的方案
6. 方案引用的地区后来从档案里删掉时，重算会在结果上方列出少了哪几条，并照剩余地区继续算；只有来源时区也被删掉、或勾选地区全部被删时才会停下报错，编辑方案重新勾选即可恢复
7. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 换算口径

- 换算按登记的标准偏移进行：先把输入的当地时刻减去来源时区的标准偏移得到基准时刻，再逐个时区加上各自的偏移
- 请求里给了 `targetIds` 就只换算勾中的地区，结果按勾选顺序出；没给时换算全部档案并按偏移排序。勾中的编号里有已经删除的档案时，对应条目放进 `missingZones`，其余地区照常换算
- 每个时区的当地日期与时刻都由基准时刻加上该时区的偏移算出，日期是否翻到前一天或后一天按公历日比较
- 写法偏好有两项：`dateStyle` 取 `iso`（2026-09-20）或 `cn`（2026 年 9 月 20 日），`timeStyle` 取 `hour24`（09:30）或 `hour12`（上午 9:30）；结果同时给出固定写法的 `localDate`、`localTime` 与按偏好写的 `localDateText`、`localTimeText`
- 与来源时区的时差按两边偏移的差值给，整小时只写小时，带分钟的把分钟也写出来
- 全部档案换算时结果按偏移从小到大排列，来源时区那一条在页面上会标出来
- 档案里登记了夏令时规则不等于换算时已经计入夏令时，规则本身如何落到具体日期上需要另行处理

## 登记口径

- 时区名称写成地区加城市，例如 `Asia/Shanghai`；基准时可以写 `UTC`；最长 40 个字符，不能重复
- 标准偏移与夏令时偏移都按整数分钟登记，范围是 -720 到 840，带半小时或三刻的地区直接写对应的分钟数（例如东五区半写 330、加德满都写 345）
- 实行夏令时的档案必须填夏令时偏移，且要比标准偏移更大（数值上更靠前）
- 切换规则分开始与结束两段，每段写清月份、第几个星期（一到四或者最后一个）、星期几、小时与分钟
- 生效年份填 1900 到 2100 之间；结束年份留空表示至今有效，已经停止实行夏令时的地区要把结束年份填上
- 备注用来写这条档案需要留意的地方，最长 200 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "zones": [...], "schemes": [...] }`。方案的每一项包括方案名、来源时区编号、勾选地区清单（连同当时的时区名与显示名一起快照）、日期与时刻写法偏好以及创建、修改时间。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据（此时方案清单为空）。

## 方案口径

- 方案名去掉首尾空白后不能为空，最长 40 个字符，与已有方案重名时保存被拒（比较时忽略大小写）
- 方案只记设置不锁时刻：重算时日期与时刻用换算台当前填的值，地区、来源时区与写法偏好用方案里存的
- 勾选地区保存的是编号加名称快照；地区档案后来被删掉时，重算结果的 `missingZones` 会按存下的名称列出少了哪几条，其余地区照算并按勾选顺序返回；列表接口也会给每条方案标出 `missingCount`
- 来源时区已被删除、或勾选地区一条都不剩时，重算返回 409 并给出说明，需要编辑方案重新选择
- 方案与换算台的当前选择是两套状态：存方案只是那一刻的复制，之后两边各自修改互不影响

## 接口一览

| 方法   | 路径             | 说明                                       |
| ------ | ---------------- | ------------------------------------------ |
| GET    | /api/health      | 服务状态检查                               |
| GET    | /api/zones       | 时区档案清单，支持按是否实行夏令时筛选与关键词搜索 |
| POST   | /api/zones       | 新增时区档案                               |
| GET    | /api/zones/:id   | 查看单条档案                               |
| PATCH  | /api/zones/:id   | 修改档案                                   |
| DELETE | /api/zones/:id   | 删除档案                                   |
| POST   | /api/convert     | 把一个时刻换算到指定（或全部）时区，请求体可带 `targetIds`、`dateStyle`、`timeStyle` |
| GET    | /api/schemes     | 换算方案清单，含各地区当前是否还在的标记   |
| POST   | /api/schemes     | 新增换算方案                               |
| GET    | /api/schemes/:id | 查看单个方案                               |
| PATCH  | /api/schemes/:id | 修改方案                                   |
| DELETE | /api/schemes/:id | 删除方案                                   |
| POST   | /api/schemes/:id/convert | 按方案重算，请求体只给当前的 `date` 与 `time`；有地区缺失时照算并在 `missingZones` 里列出 |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
