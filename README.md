# tp125 时区与时间换算工作台

一个本地小工具：把各地时区连同夏令时规则登记进来，再把某一个时刻换算到已登记的时区，页面上直接看出各地是当地的几点、谁的日期已经翻到前一天或者后一天、跟来源时区差了几个小时。常看的一组地区与写法偏好可以存成换算方案，之后点开方案就能按它重算。时区名写得不合规矩、偏移超出范围、夏令时偏移不比标准偏移靠前、开始与结束两段规则写得一模一样、结束年份早于开始年份，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5125>

端口固定为 `5125`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 时区档案区列出时区名称、显示名称、标准偏移、是否实行夏令时、夏令时偏移、切换规则、生效年份与备注；可以按是否实行夏令时筛选，也能按名称、显示名或备注搜索
2. 点新建档案填上时区名与偏移；实行夏令时的档案还要把夏令时偏移与开始、结束两段切换规则（第几个星期几的几点几分）以及生效年份填上
3. 换算台选好日期、时刻与来源时区，在「换算地区」里勾选要看的地区（默认全选），挑好日期与时刻的写法，点换算一遍，页面列出每个选中时区的当地日期、当地时刻、星期、与来源是否同一天、偏移以及跟来源时区差多少
4. 常看的一组设置可以点「存为方案」取个名字存下来：勾选的地区、来源时区、日期与时刻的写法都会记进方案；方案区列出所有方案与各自存下的时间，点「按方案重算」就按方案的设置重算一遍（日期与时刻用换算台当前填的）
5. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 换算方案口径

- 方案记下：名字、选中的地区（连同当时的名称快照）、来源时区、日期写法（年-月-日、中文写法、日/月/年、月/日/年）与时刻写法（24 小时制、12 小时制），以及存下与最后修改的时间
- 方案名不能为空，也不能与已有方案重名（不分大小写）；最长 40 个字符
- 按方案重算时，日期与时刻取自换算台当前填的内容，其余一律按方案存的设置；换算用的是档案里的最新偏移，方案只记引用
- 方案引用的地区后来被删掉时，重算会点名少了哪几个，剩下的地区照常换算，不会整个失败；来源时区被删则没有了折算基准，会明确指出并提示先编辑方案
- 方案与换算台各看各的：改方案不影响正在显示的换算结果，在换算台上改勾选、改写法也不会悄悄改动任何方案；方案列表里能看出每个方案自己的设置，与页面当前选择分开对照

## 换算口径

- 换算按登记的标准偏移进行：先把输入的当地时刻减去来源时区的标准偏移得到基准时刻，再逐个时区加上各自的偏移
- 每个时区的当地日期与时刻都由基准时刻加上该时区的偏移算出，日期是否翻到前一天或后一天按公历日比较
- 与来源时区的时差按两边偏移的差值给，整小时只写小时，带分钟的把分钟也写出来
- 结果按偏移从小到大排列，来源时区那一条在页面上会标出来
- 档案里登记了夏令时规则不等于换算时已经计入夏令时，规则本身如何落到具体日期上需要另行处理

## 登记口径

- 时区名称写成地区加城市，例如 `Asia/Shanghai`；基准时可以写 `UTC`；最长 40 个字符，不能重复
- 标准偏移与夏令时偏移都按整数分钟登记，范围是 -720 到 840，带半小时或三刻的地区直接写对应的分钟数（例如东五区半写 330、加德满都写 345）
- 实行夏令时的档案必须填夏令时偏移，且要比标准偏移更大（数值上更靠前）
- 切换规则分开始与结束两段，每段写清月份、第几个星期（一到四或者最后一个）、星期几、小时与分钟
- 生效年份填 1900 到 2100 之间；结束年份留空表示至今有效，已经停止实行夏令时的地区要把结束年份填上
- 备注用来写这条档案需要留意的地方，最长 200 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "zones": [...], "presets": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径                  | 说明                                       |
| ------ | --------------------- | ------------------------------------------ |
| GET    | /api/health           | 服务状态检查                               |
| GET    | /api/zones            | 时区档案清单，支持按是否实行夏令时筛选与关键词搜索 |
| POST   | /api/zones            | 新增时区档案                               |
| GET    | /api/zones/:id        | 查看单条档案                               |
| PATCH  | /api/zones/:id        | 修改档案                                   |
| DELETE | /api/zones/:id        | 删除档案（返回引用了它的方案名）           |
| POST   | /api/convert          | 把一个时刻换算到指定（或全部）已登记的时区 |
| GET    | /api/presets          | 换算方案清单                               |
| POST   | /api/presets          | 新增换算方案                               |
| GET    | /api/presets/:id      | 查看单个方案                               |
| PATCH  | /api/presets/:id      | 修改方案                                   |
| DELETE | /api/presets/:id      | 删除方案                                   |
| POST   | /api/presets/:id/run  | 按方案重算（日期与时刻由请求带上）         |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
